# AGENTS.md

## Language

Default to Chinese in user-facing replies unless the user explicitly requests another language.

## Response-Style

- 先给结论或结果，再给必要依据；常规回复保持精炼。
- 不确定时说明假设和风险；低风险歧义可直接合理假设并继续，高风险或不可逆操作先确认。
- 不编造文件、命令、测试结果、执行结果或不存在的项目约定。

## Execution Rules

- 在执行多步骤任务前，应简要说明命令目的。非平凡任务给短计划，简单任务直接完成。
- 先理解真实上下文，再修改代码；优先读相关文件、文档、配置、测试和已有实现。
- 优先最小必要改动，复用现有实现、项目风格、命名习惯和工具链。
- 不做无关重构、无关格式化、无关文件修改或任务外扩展。
- 独立子任务可并行探索；最终判断、代码修改和风险取舍由主线程负责。

## Debug-First

- 修复问题时先复现或定位根因，再改代码。
- 同一问题连续修复失败时，停止堆补丁，重新分析根因和调用链。
- 不用静默 fallback、mock 成功路径或吞错掩盖真实问题。
- fallback、降级或兼容路径必须有明确触发条件、可测试，并说明影响。
- 结构性问题不要只打补丁；出现重复逻辑、多处真相源、共享校验、API 契约漂移、隐藏 fallback、反复 bug、状态同步或安全/数据完整性边界时，先找不变量，并让代码在一个地方表达它。

## Code-Quality

- 代码应简单、清晰、可测试、可维护；优先短函数、浅嵌套、少参数和 guard clause。
- 避免编写无依据的防御性代码或兜底规则，这只会增加维护成本
- 避免魔法数字、重复逻辑、隐式全局状态、未使用代码和无意义抽象。
- 注释解释设计意图、边界条件或关键取舍，不重复代码表面含义。
- 核心业务逻辑尽量与 IO、外部服务和框架 API 解耦。
- 修改前检查工作区状态；不覆盖、回滚或删除用户已有改动，除非用户明确要求。
- 只修改与当前任务直接相关的文件；使用直接、逐文件、便于人工审阅的修改方式。
- 不为省事编写一次性脚本、批量替换、codemod、跨文件自动迁移或批量格式化；确需使用时先说明范围和影响，并获得明确确认。
- 不把临时调试代码、无关日志或中间产物留在项目中。

## Security-Baseline

- 不硬编码密钥、密码、token、API Key、私钥、证书等敏感信息。
- 外部输入在系统边界校验；不主动降低认证、授权、权限、支付、审计或数据保护相关校验。
- 依赖、锁文件、数据库迁移、生产配置、CI/CD、安全策略、支付或用户数据相关改动，必须先说明必要性和影响。
- 对于删除、移动、重命名、批量改写、`git reset`、`git clean` 等破坏性命令或可能导致丢失、覆盖或重写用户工作内容的操作执行前，必须获得明确授权。
